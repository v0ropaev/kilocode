# Security Auto Mode — LLM-прослойка поверх детерминированного контура

Статус: реализовано как **опциональный эксперимент**, выключенный по умолчанию.
Флаг: `experimental.security_auto_classifier` / `KILO_SECURITY_AUTO_CLASSIFIER`.

## 0. Где именно стоит модель

```
   ┌──────────────── действие агента (tool call) ────────────────┐
   ▼                                                             │
[ Deterministic Security Engine ]  ← ИСТОЧНИК ПОЛНОМОЧИЙ         │
   • опасные команды / защищённые пути / package policy          │
   • Capability / CodeTrust (кто вправе выполнять)               │
   • Session State (читал ли секрет в этой сессии)               │
   → набор evidence → свёртка → ALLOW / soft-ASK / hard-ASK / DENY
   │                                                             │
   ├─ DENY или hard-ASK ──────────────────────► модель не вызывается вообще
   ├─ действие без сети ──────────────────────► модель не вызывается вообще
   │                                                             │
   └─ ALLOW / soft-ASK на исходящем действии                     │
             ▼                                                   │
   [ LLM Advisory ]  → одна из двух вещей:                       │
             │          • ничего (evidence не добавлено)         │
             │          • одно evidence «ask»                    │
             ▼                                                   │
   та же монотонная свёртка ────────────────────────────────────┘
             ▼
   [ OS Sandbox / Extension Runtime ]  ← ограничивает даже после ALLOW
             ▼
        выполнение
```

Ключевое отличие от первоначального плана: модель **не возвращает решение**. Она возвращает
свидетельство, которое попадает в ту же свёртку, что и все остальные слои.

## 1. Почему инварианты — свойство кода, а не обещание

`Decision.reduce` сворачивает список evidence функцией `stricter()`, начиная с `allow`. Добавление
элементов может сдвинуть решение только в сторону ASK/DENY и никогда обратно. Слой, который умеет
**только дописывать** evidence, структурно неспособен что-либо ослабить.

Отсюда, без единой проверки вида «если DENY, то верни DENY»:

1. Детерминированный `DENY` остаётся `DENY` при любом ответе модели.
2. `hard-ASK` не понижается.
3. Модель не может выдать `ALLOW` — это нейтральный элемент свёртки, а не значение, которое слой
   способен внести.
4. Модель не может выдать и `DENY`. Слой вносит `ask`: он вправе потребовать человека, но не вправе
   сам завершить задачу.

Что изменилось по сравнению с прототипом: там `soft-ASK` + «модель говорит, что намерение совпадает»
превращалось в `ALLOW`. Это ровно та композиция, которую тезис проекта исключает — модель становится
несущей для **разрешения**, и репозиторий, способный поговорить с моделью, договаривается об отмене
запроса. Вместе с ней убран и вопрос «просил ли это пользователь»: `SecurityGate.evaluate` получает
запрос, опции, идентификатор сессии и имя агента — пользовательского промпта там нет, поэтому
ответить на такой вопрос можно было только по выдуманным данным.

## 2. Полоса вызова

Модель спрашивают только там, где детерминированные слои не дали достаточного ответа:

| Ситуация | Модель вызывается |
|---|---|
| `DENY` | нет — вопрос уже решён |
| `hard-ASK` | нет — прогон и так остановлен, вызов добавил бы только задержку |
| действие без сети | нет — обычная локальная работа, движок её понимает |
| `ALLOW` / `soft-ASK` на исходящем действии | да |

Измеренная доля: **0.18 вызова на решение** — примерно одно решение из шести.

## 3. Отказ неотличим от выключенного слоя

Нет провайдера, таймаут, ошибка транспорта, ответ вне словаря — во всех случаях слой возвращает
пустой список evidence, то есть детерминированное решение остаётся ровно таким, каким было.
Это и есть гарантия «с выключенным флагом продукт ведёт себя как раньше»: она проверена не рассуждением,
а прогоном — все 187 сценариев дают побайтово одинаковые решения, коды причин и счётчики.

Дедлайн — `AbortSignal`, а не гонка промисов: зависший провайдер должен быть отменён, а не оставлен
работать в фоне. Бюджет `KILO_SECURITY_AUTO_CLASSIFIER_TIMEOUT_MS`, по умолчанию 300 мс.

## 4. Что модель видит и почему это безопасно

Только структурное описание действия: программа, факт выхода в сеть, вид файлового эффекта, для
каждого операнда — **имя файла без каталога**, класс расположения и метки. Ни командной строки, ни
путей, ни содержимого.

Имя файла выбирает репозиторий, то есть это недоверенный вход. Он размечен как данные и обёрнут в
`<action>`. Принципиально же его безопасность обеспечивается не разметкой: слой умеет только
ужесточать, поэтому подобранное имя или встроенная инструкция способны лишь **отменить ужесточение**,
которое иначе произошло бы. Открыть что-либо они не могут.

Словарь ответа закрыт: `RISKY` или `ORDINARY`, разбор точный. Прототип сравнивал по префиксу `/^y/i`
и прочитал бы «You must not do this» как согласие — единственная ошибка разбора, способная превратить
текст модели в более слабый исход.

## 5. Провайдеры

| Провайдер | Когда | Замечание |
|---|---|---|
| `heuristic` (по умолчанию) | офлайн-прогоны, CI | детерминированный, без сети и ключей; **не модель**, а заглушка для проверки композиции |
| `anthropic` | small-модель через API | отправляет описание действия наружу — учитывать в корпоративном контуре |
| `openai` | локальный Ollama / совместимый сервер | вариант для контура без внешних вызовов |

Настройка: `KILO_SECURITY_AUTO_CLASSIFIER_PROVIDER`, `_MODEL`, `_URL`, `_KEY`, `_TIMEOUT_MS`.

## 6. Что осталось нереализованным

**Context Checker** — сканирование недоверенного входа (README, результат MCP, веб-страница) на
инструкции, адресованные агенту. Его место — `SecurityGate.execute`/`delegate`, где `observeContent`
уже разбирает то, что инструмент реально вернул. Сегодня это синхронная функция, а вызов модели —
асинхронный, поэтому слой требует перестройки пути `settle`, а не только нового файла. Не сделано.

Без него advisory судит действие, а не источник инструкции, — поэтому он ловит исходящую передачу и
не отличает «агент сам решил» от «репозиторий его попросил».

**Phase 0 — детерминированные фиксы найденных дыр.** Из четырёх сделана одна:

- [x] каналы egress: `curl -F`, `--data-urlencode`
- [ ] taint по значению за `cp` / `mv` / `sed` / `awk` / кодированием
- [ ] анализ аргументов интерпретаторов: `python -c`, `node -e`, `perl -e`
- [ ] `git stash -u`

Три оставшихся — это подтверждённые бенчмарком остаточные классы, а не гипотезы.
