# Диаграммы

`architecture.mmd` — каноничный слоёный ход решения: вызов инструмента проходит нормализацию,
`SecurityGate` и `SecurityEngine`, слои признаков подают свидетельства тому же монотонному правилу
свёртки, и решение `ALLOW / ASK / DENY` доходит до исполнителя. Отдельно показаны две границы,
работающие до появления вызова: Executable Code Trust и Permissioned Extension Runtime с
Read-Confinement. Граница доверия между недоверенной стороной и тем, что её удерживает, отмечена
явным узлом.

`evaluation-loop.mmd` — цикл измерения: найти атаку, воспроизвести в одноразовом окружении,
поставить канарейку, снять состояние без защиты, снять защищённое, измерить долю успешных атак, долю
выполненных задач, ошибочные срабатывания, нагрузку на человека и задержку, зафиксировать новый
остаток и вернуться к началу.

Рендер: содержимое файла вставляется в блок с языком `mermaid` и рисуется в GitHub, Obsidian и
большинстве просмотрщиков Markdown; в SVG — `mmdc -i architecture.mmd -o architecture.svg`.

Презентация воспроизводит структуру обеих схем нативными фигурами, а не вставленной картинкой: эти
файлы — источник структуры и подписей, а не готовый экспорт. Числа в схемы не выносятся, их
источник — `submission/SOURCE_OF_TRUTH.md`.
