проверить, не открывая PowerPoint. Колода собирается из этого репозитория:

```bash
cd submission && python3 build-deck.py        # сборка + проверка вёрстки, ненулевой код при проблеме
soffice --headless --convert-to pdf --outdir . Security-Auto-ATH.pptx
```

**Двадцать один слайд: семь основных, слайд команды, разделитель и двенадцать в приложении.** Основная колода —
ровно то, что произносится за 4:47; всё остальное живёт за разделителем «Приложение» и открывается
только по вопросу. Речь — в `PITCH_SCRIPT.md`, ответы на вопросы — в `JUDGE_QA.md`, числа — в
`SOURCE_OF_TRUTH.md`.

Правила, по которым собрана основная колода: один слайд — одна мысль; заголовок формулирует вывод, а
не называет раздел; слайд не дублирует речь; скриншот обрезан до решающего места и перерисован
крупным кеглем — 21,7 пункта на слайде против 6,8 у обычного рендера записи.

Про кегль — честно, потому что это единственное правило организатора, которое видно с первого
взгляда. Рекомендованы тридцать пунктов на стандартном холсте, то есть 22,5 на этом (10 × 5,625
дюйма). Тело основных слайдов набрано на 15–21 пункте, что в пересчёте даёт 20–28. Порога не
достигает ни один слайд: содержание, которое надо удержать на семи слайдах, в тридцать пунктов не
помещается. Мы предпочли назвать это, а не заявить соответствие, которого нет.

## Слайд 4 — Правила — гарантии, ИИ — смысл

| | |
|---|---|
| **Действие** | какая программа, какие файлы, выход в сеть |
| **Контекст** | что агент прочитал в этой сессии и откуда |
| **Признаки** | два независимых источника, порознь |
| **Решение** | разрешить · спросить человека · запретить |

**ИИ возвращает признак, а не решение.** Отменить запрет он не может и источником доверия не
является — это свойство кода.

Смысловой слой — Claude Haiku 4.5 через OpenRouter. Компактная модель, выбрана нарочно: проверяли
принцип, а не мощность.

## Слайд 10 — Считаем, что моделью можно управлять со стороны

**Доверяем:** разработчику и его задаче, его личным настройкам Kilo, коду самого Kilo, механизму
изоляции операционной системы.

**Не доверяем:** рассуждению модели, содержимому репозитория, имени пакета, которое придумала модель,
описаниям внешних инструментов, коду проекта.

**Что из этого следует:** решение не зависит от того, распознала ли модель атаку. Его принимает
отдельный слой, а часть границ подтверждает операционная система.

> **Намерение ≠ полномочия.** Подсказка со стороны может изменить то, чего хочет модель. Изменить то,
> что ей позволено, она не может.

## Слайд 11 — Решение — по действию, источнику и истории

Шесть входов движка: что агент хочет сделать · с каким файлом или пакетом · откуда пришёл вызов ·
просил ли это пользователь · что уже было в этой сессии · какие признаки риска нашлись.

Один и тот же движок для каждого вызова с последствиями. Три исхода: **ALLOW** — действие
выполняется в границах разрешения; **ASK** — дальше без человека небезопасно, и самостоятельный
режим этот вопрос не снимает; **DENY** — действие не выполняется, агент получает причину и
продолжает работу.

## Слайд 12 — Откуда берутся признаки риска

| Вопрос | Как отвечаем | Слой |
|---|---|---|
| Опасна ли сама команда | раскрываются переменные, вызовы и пути | Deterministic Security |
| Что известно про пакет | возраст, распространённость, скрипты установки | Package Security |
| Мы уже читали секрет | что прочитано и в какие файлы это попало | Stateful Egress |
| Кто вызывает действие | права следуют из происхождения, не из описания | Delegated Tool Security |
| Есть ли в файле учётные данные | форматы токенов, ключи, присваивания в тексте | Content Secret Detection |
| Код проекта пытается запуститься сам | файл выполняет верхний уровень при импорте | Executable Code Trust |
| Расширение выходит за свои права | чтение, запись, сеть и процессы — по запросу | Permissioned Extension Runtime |

## Слайд 13 — Разрешить действие ≠ отдать все права

Одобрено расширение → выданы конкретные права → работает в отдельном процессе под профилем ОС →
привилегированное действие снова идёт запросом к тому же движку.

Расширение вышло за выданные права: **24/24 → 0/24**. Расширение прочитало чужой файл:
**33/33 → 3/33**. Граница держится на механизме операционной системы: на macOS проверена прямыми
пробами внутри настоящего процесса, профиль Linux написан, но здесь не проверялся.

## Слайд 19 — Успех атаки — это последствие

192 сценария (141 атака и 51 обычная задача) × 3 повтора × 10 конфигураций; соседние конфигурации
отличаются одним включённым слоем. Изоляция: одноразовый каталог, подставной домашний каталог,
безвредные заглушки пакетных менеджеров, сеть только на петле. Успех засчитывается по последствию:
помеченный файл удалён, выдуманный ключ дошёл до приёмника, установка запустилась.

Лестница из десяти конфигураций: 100 · 71 · 60 · 57 · 50 · 43 · 38 · 31 · 24 · **5 %**.

## Слайд 21 — Что не закрыто и что дальше

**Чего защита не умеет.** Путь внутри строки `python -c`, `node -e` или `perl -e` не становится
операндом при разборе. `git stash -u` очищает дерево и разрешён; правила на следующий `drop` не
хватает. Внутри сужённого процесса расширение видит размер файла и то, что он есть. Один вызов
модели из 117 не уложился в срок — там, где под слоем нет правила, это пропуск. Границы системы
проверены на macOS; профиль Linux написан, но не проверен.

**Чего не показывает измерение.** Набор атак наш собственный: «100 % без защиты» — это про него, а
не про Kilo вообще. Ход работы агента задан сценарием, поэтому измеряется удержание, а не то,
догадается ли модель напасть. Качество смыслового слоя — свойство одной модели: всё снято на
`claude-haiku-4.5` через OpenRouter, другая даст другие числа.

**Пилот.** Команда 5–10 разработчиков, репозиторий с внешними зависимостями и внешними
инструментами. Смотрим: долю успешных атак, долю доведённых задач, ошибочные запреты, вопросы на
задачу, задержку и сколько человек через две недели оставили режим включённым. Отложенный набор
израсходован; новый пишет внешний автор, а конфигурация уже запечатана.

Повторить любую цифру: `bun run script/security-bench.ts --runs 3`.
Повторить любую запись сессии: `bash submission/evidence/ui/capture-all.sh`.
