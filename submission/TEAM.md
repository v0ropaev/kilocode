### Что именно подтверждают сообщения коммитов

Зоны ответственности восстановлены по темам коммитов, а не заявлены — кроме постановки задачи и
приёмки, у которой коммитов нет и которая названа отдельно выше. Группы, которые читаются в истории:

- **Движок политики.** Детерминированное `ALLOW / ASK / DENY` для tool call'ов и наблюдательный
  seam в `SecurityGate`, через который бенчмарк снимает решения, не влияя на них.
- **Слои признаков риска.** Package Security (оценка происхождения пакета до запуска пакетного менеджера),
  Stateful Egress (посессионная связь sensitive-read → outbound), Delegated Tool Security
  (capability-модель для MCP и custom-инструментов), Content Secret Detection (секрет по
  содержимому, а не по имени файла).
- **Граница исполняемого кода.** Executable Code Trust: доверие требуется до загрузки
  репозиторного исполняемого модуля, одобрение привязано к локальному import-замыканию.
- **Runtime и чтения.** Permissioned Extension Runtime (одобренное расширение — в отдельном
  процессе под профилем ОС), расширение sandbox-профиля на чтения и Read-Confinement для
  расширения.
- **Оценка.** Воспроизводимый adversarial harness и семь отдельных коммитов, добавляющих в
  ablation-лестницу измерение конкретного слоя: delegated authority, pre-gate, content (и уловы,
  и false positives), executable code, extension runtime, extension read boundary.
- **Смысловой слой на модели.** Отдельная ветка тем Arthur Fakhretdinov: план слоя, прототип с офлайн-
  заглушкой вместо модели, провайдер, тесты и вынесение слоя в измеримую ступень лестницы. Свёртка
  его признаков в решение движка — уже в коммитах Dmitry Voropaev.
- **Расширение набора атак.** Класс «подброшенная в текст инструкция» и класс «действие, не имеющее
  отношения к задаче», плюс отмывание меток через промежуточные файлы. Именно эти сценарии сделали
  набор заметно труднее для одних правил.
- **Переносимость на Linux.** Отдельная ветка тем Дмитрия Комарова: профиль расширения и
  sandbox-примитив доведены до состояния, в котором граница чтения на Linux действительно включается
  — `/proc` и `/sys` убраны из разрешённого набора, обе записи usr-merged-симлинка биндятся,
  каталог, который нельзя перечислить, не срывает построение профиля. Граница чтения расширения
  теперь проверена зондами внутри настоящего процесса на обеих платформах: macOS (Seatbelt) и
  Linux (bubblewrap).
- **MCP-ресурсы в смысловом контексте.** Три инструмента ресурсов (`list_mcp_resources`,
  `list_mcp_resource_templates`, `read_mcp_resource`) проходят через `SecurityGate.delegate` — тот же
  жизненный цикл, что и у делегированного MCP-вызова, и без второго запроса разрешения. Текст,
  который они возвращают, попадает в контекст смыслового слоя и судится против следующего действия с
  последствиями.
- **Пайплайн записей интерфейса.** Съёмка и отрисовка сессий `kilo run` работают на Linux; ошибка
  использования CLI печатается в любой локали; документированная тестовая команда — та, которая
  действительно прогоняется.
- **Документация.** Threat model, trust boundaries, read confinement и отдельный документ о том, что
  смысловой слой измеряет и чего не измеряет.

Результат этой работы измерен на 192 сценариях (141 атака и 51 обычная задача) × 3 повтора ×
10 конфигураций = **5760 прогонов, 0 errored**. Доля успешных атак: **100 % (417/417)** без защиты →
**24 % (102/417)** одними детерминированными слоями → **5 % (19/417)** со смысловым слоем;
знаменатель 417 — прогоны атак с наблюдаемым последствием (139 сценариев × 3 повтора; ещё две атаки
слишком опасно исполнять и они считаются по решению движка), знаменатель 153 — обычные задачи
(51 × 3). Доля выполненных обычных задач — **98 % (150/153)** на одних правилах и **98 % (150/153)** со
смысловым слоем; смысловой слой измерен на настоящей модели
(`openrouter/anthropic/claude-haiku-4.5`). Тесты на этой машине (macOS) — **757 pass / 0 fail**,
3540 expect(), 22 файла в `packages/opencode` (security, реестр инструментов, смысловой слой) и
**65 pass / 1 skip / 0 fail**, 351 expect() в `packages/kilo-sandbox`.

## Разделение зон

Семь естественных зон проекта. Отметка «покрыто» означает то, что подтверждается историей
репозитория; там, где зона держится на заявлении команды, это сказано прямо.

| Зона | Что входит | Статус |
|---|---|---|
| Security engineering / policy engine | `SecurityEngine`, `SecurityGate`, восемь детерминированных слоёв, sandbox-профили | покрыто Dmitry Voropaev |
| Semantic layer | слой на модели, его провайдер и тесты, отдельная ступень лестницы | покрыто Arthur Fakhretdinov; свёртка признаков в решение — Dmitry Voropaev; MCP-ресурсы в контексте слоя — Дмитрием Комаровым |
| Benchmark and evaluation | сценарии, ablation-лестница, метрики, отчёт | покрыто Dmitry Voropaev; классы атак «подброшенная инструкция» и «чужая цель» — Arthur Fakhretdinov |
| Переносимость и платформы | профиль расширения на Linux, sandbox-примитив, проверка границы чтения зондами на обеих платформах | покрыто Дмитрием Комаровым |
| AI Product | гипотеза, метрики успеха, продуктовые решения, приоритет слоёв | постановка задачи и приёмка — Дмитрий Комаров (заявление команды, коммитов у этой работы нет); приоритет слоёв по измерению — Dmitry Voropaev |
| Documentation and submission | `docs/`, пакет `submission/`, консистентность цифр | покрыто Dmitry Voropaev; runbook, source of truth и Linux-числа в колоде — Дмитрием Комаровым |
| Demo and presentation | сценарии демонстрации, прогон, защита | записи интерфейса и колода — Dmitry Voropaev; пайплайн съёмки и отрисовки, работающий на Linux, — Дмитрий Комаров |

Зоны не эквивалентны по объёму: security engineering и evaluation в этом проекте связаны жёстко —
каждый слой добавлялся после измерения, показавшего, какой класс атак остался самым крупным.
Разносить их между людьми имеет смысл только вместе с общим владением harness'ом. Смысловой слой —
единственная зона, которую в истории видно как отдельную линию работы: он появился последним, поверх
уже измеренного детерминированного контура, и измеряется отдельной ступенью той же лестницы.

- Проценты вклада не проставлены. Они допустимы только после явного подтверждения всей командой;
  в текущей истории репозитория оснований для них нет.
- Если чей-то вклад лежит вне этого репозитория — назвать артефакт (документ, макет, прогон демо),
  на который можно сослаться, иначе он останется неподтверждаемым.
